## 定价 $19 → $9.9（Wedding Image Pack）

改动前先把「价格到底写在哪」摸清了，结论是**三处**，缺一不可：

1. `src/config/locale/messages/<locale>/pages/pricing.json`
   - `page.sections.pricing.items[1].amount`: `1900` → `990`（**这是真正被扣款的金额**，单位分）
   - `page.sections.pricing.items[1].price`: `"$19"` → `"$9.9"`（展示用）
   - `metadata.description`: `...for $19.` → `...for $9.9.`
2. `src/config/locale/messages/<locale>/pages/design.json`
   - `unlock_cta`: `"Unlock for $19"` → `"Unlock for $9.9"`
3. `src/themes/default/blocks/wedding-result.tsx:758`
   - 硬编码的 `<p className="mt-4 font-serif text-2xl">$19</p>` → `$9.9`

共 8 个语言目录（de/en/fr/it/ko/pt-BR/th/zh）× 2 文件 + 1 个 tsx = 17 个文件。
校验：全仓 `$19|1900` 零残留；16 个 JSON 全部 `JSON.parse` 通过。

### 关键链路事实（以后改价直接照这个走）

- `/api/payment/checkout` **完全不信任前端传的金额**：只收 `product_id`，
  金额由它自己 `loadMessages('pages/pricing', locale)` 从上面的 locale JSON 里读
  `pricingItem.amount`。所以改 `amount` 就等于改真实收款价，不用动 API。
- `pricing.json` 里**没有** `payment_product_id` / `currencies` / `original_price`，
  因此不存在「渠道侧固定商品价覆盖本地金额」的走法（`getPaymentProductId` 仅对 creem 生效，
  且会先看 `configs.creem_product_ids`）。若线上后台配了 creem 商品映射 / stripe price id，
  还得去渠道后台同步改价——这点未验证。
- 首页定价模块与 `/pricing` 页共用同一份 `pages/pricing` 配置
  （`app/[locale]/(landing)/page.tsx` 与 `.../pricing/page.tsx` 都 spread `page.sections.pricing`），
  改一处即全站生效；landing.json / pages/index.json / content/*.mdx 里都没有价格文案。
- 历史遗留：`artifacts/crest-generation-one/{original,modified}/` 里有一份旧的
  design.json 快照仍写着 $19，属于归档产物，**未改动**。
