# 2026-09-08

## GSC Coverage「Duplicate without user-selected canonical」修复

- 用户提供了 `weddingcrestdesign.com-Coverage-Drilldown-2026-09-08.xlsx`（GSC 覆盖率钻取），问题类型为 `Duplicate without user-selected canonical`，共 7 条 URL：
  - `/create?style=vintage_engraving&exampleId=...`、`/create?style=botanical_watercolor&exampleId=...`（参数变体）
  - `/fr/wedding-crest-generator`、`/zh/wedding-crest-generator`、`/de/wedding-monogram-maker`、`/th/wedding-monogram-maker`、`/fr/wedding-logo-maker`（多语言变体）
- 根因：`create`、`wedding-crest-generator`、`wedding-logo-maker`、`wedding-monogram-maker` 4 个页面的 `generateMetadata` 只返回 title+description，没有 `alternates.canonical` 也没有 hreflang `languages`（其他 SEO 页面用 `@/shared/lib/seo` 的 `getMetadata()`，自带 canonical+hreflang）。
- 修复：在 `src/shared/lib/seo.ts` 抽离导出 `getAlternates(canonicalUrl, locale, appUrl)`（canonical + 全语言 hreflang + x-default），`getMetadata` 改为复用它；4 个页面各自调用 `getAlternates('<相对路径>', locale, envConfigs.app_url)`。
- 校验：eslint 0 报错、`tsc --noEmit` 通过。
- 提交：`c23b979`（分支 `cf`），已 push 到 origin/cf，随后 `npm run cf:deploy`。

### 复用经验
- 站点任何「可索引」页面的 metadata 都必须带 canonical + hreflang，否则会被 Google 判定重复。新页面若不走 `getMetadata()`，至少要接 `getAlternates()`。
- canonical 基础域名用 `envConfigs.app_url`（生产 resolveAppUrl 兜底为 https://weddingcrestdesign.com），保证 https。
